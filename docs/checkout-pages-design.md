# SRMS 退租结算与退租退款页面设计（V1.1）

## 1. 页面范围

本设计覆盖发起退租、退租结算、退租退款确认三个页面。

## 2. 发起退租

管理员选择合同，填写退租类型、计划退房日期、房屋交接日期、退租原因、验收时间和退房后目标房源状态。

发起后：

- 合同变为`PENDING_CHECKOUT`。
- 房源变为`PENDING_CHECKOUT`。
- 未来账单暂不删除，待结算确认后按实际退房日作废。
- 系统展示押金、欠租、预收款和未来账单快照。

## 3. 退租结算

房屋验收完成后，管理员登记欠租、维修扣款、其他双方确认的扣款项目，以及需要从已缴租金中回冲的“退还租金”。第一版不包含水电费。

“结算项目”标题右侧并列显示“添加退还租金”“添加欠租”“添加验房扣款”。退还租金每张结算单最多一项，管理员只填写：

- 退还金额：必填且大于0；
- 退还说明：必填，1至500个字符；
- 删除：仅在结算仍可编辑时显示。

页面显示“当前最多可退租金 ¥X.XX”和系统建议回冲明细。管理员不选择账单、收款或分配记录；实际退房日期、合同或关联退款状态变化后，页面重新请求后端预览。

可回冲范围只包括实际退房日之后的未来账期和包含实际退房日的当前账期。系统优先按未来账期开始日从晚到早，再按同账单的收款日期和分配ID从大到小，最后处理当前账期；实际退房日前已结束的历史账期不参与回冲。

计算口径：

```text
应退押金 = max(0, 押金余额 - 抵扣欠租 - 已确认的其他扣款)
应退租金 = 管理员填写且不超过后端计算上限的退还租金
租客仍需补交 = max(0, 欠租与扣款合计 - 押金余额)
最终退款合计 = 押金可退金额 + 应退预收款 + 应退租金
```

退还租金单独进入应退款，不与欠租、验房扣款互相抵扣。扣款仍必须关联欠租账单、房屋验收记录或上传的证明材料。

提交结算时，后端在事务中重新计算可用余额并生成“已预留”回冲明细。普通退款、收款作废和其他退租流程不能重复占用同一租金分配；发生并发冲突时显示中文提示并要求刷新。

结算确认后锁定押金、预收款、租金三类应退金额及回冲明细，作废退房日之后的未来未收账单，但合同仍保持待退房。驳回、退回草稿、取消结算或合同纠错取消尚未退款的结算时，已有租金回冲预留转为“已释放”。

如租客仍需补交，必须完成补收后才能进入退款或合同结束。预收款余额也必须完成退款或其他经批准的处理。

## 4. 退租退款确认

管理员登记、超级管理员确认。页面不要求填写收款人、退款账户后四位或交易流水号，只填写退款日期、方式和备注，并上传一份合并退款凭证。

页面只读展示：

- 应退押金；
- 应退预收款；
- 应退租金；
- 合计退款；
- 系统锁定的租金回冲明细，包括原收款、原账单和回冲金额。

退款总额由后端按照三类锁定金额计算，客户端不能提交或修改拆分金额。三类金额只用于内部分类，财务中心只登记一笔合计退款的外部资金流出。

非零退款必须上传交易截图或PDF；现金退款上传租客签字凭证。确认时校验：

- 房屋已完成交接。
- 结算单已经确认。
- 欠租和扣款已结清或用押金抵扣。
- 租客待补交金额为0。
- 预收款余额已处理。
- 押金、预收款、租金三类拆分合计等于结算单锁定的退款总额。
- 租金回冲预留仍完整且未被其他流程占用。
- 至少存在一张有效退款凭证。

超级管理员点击“确认退款并完成退租”后，在同一数据库事务中完成租金回冲、同额减少账单净应收与有效实收、更新原收款退款状态、写押金及预收款退款流水、锁定凭证、完成结算、结束合同并将房源更新为验收时选定的状态。任一步失败时全部回滚。

如三类应退款合计为0，结算确认通过上述结束条件后仅超级管理员可直接完成退租，无需伪造0元退款记录或上传退款截图。

## 5. 权限

- 管理员：添加、编辑、删除退还租金项目，提交结算，查看系统回冲明细，登记合并退款并上传凭证。
- 超级管理员：拥有管理员权限，并可确认结算和最终确认合并退款。
- 游客：仅可查看，无提交、确认或上传权限。

权限必须由后端强制校验；前端隐藏按钮只用于改善体验。

## 6. 撤销与审计

已确认退款不能删除或直接修改。确需纠错时，必须通过已批准的合同作废/纠错流程逆转；原退款、凭证、回冲和结算记录永久保留。普通操作日志可以由超级管理员隐藏，但对应安全审计日志不可删除。

## 7. 验收标准

- 发起退租不会提前作废未来账单或结束合同。
- 押金可正确抵扣欠租和经确认的验房扣款。
- 扣款没有依据时不能提交结算。
- 管理员只填写退还金额和说明，系统显示并强制执行可退租金上限。
- 自动回冲顺序固定、明细可追溯，历史已履行账期不参与回冲。
- 普通退款、收款作废、另一退租结算与当前退租不能重复占用同一租金分配余额。
- 驳回、退回草稿、取消和合同纠错能释放未生效的租金回冲预留。
- 结算确认后才作废实际退房日之后的未来账单。
- 存在待补交、未处理预收款或未退款金额时不能结束合同。
- 非零合并退款没有凭证时不能确认。
- 不要求收款人、账户后四位和交易流水号。
- 最终确认同额减少账单净应收和有效实收，不新增未收；原收款状态正确变为部分退款或全部退款。
- 押金、预收款和租金合并为一次退款，财务中心只统计一笔外部资金流出。
- 最终确认任一步失败时全部回滚；并发确认只能有一个成功。
- 退款确认后合同结束、押金与预收款余额正确、房源状态正确更新。
- 所有页面提示、状态和日期展示为中文。
