# 退租结算重设计验收记录

日期：2026-08-11

## 范围

- 三步工作区：发起退租、退租结算、押金退还确认。
- 结算审批后合同和房源保持待退租；只有最终退款确认或零金额最终确认后才结束合同并更新房态。
- 退款总额固定为锁定的应退押金加应退预收款；审批时分别记入押金退款和预收款退款流水。
- 零金额退款无需上传凭证，仅超级管理员可最终确认。
- 后端详情接口返回退租页面所需的合同、房源、结算项目、退款摘要和两位小数金额字符串。

## 新合同押金自动入账联动（2026-08-24）

- 适用批准变更：`SRMS-RB-1.0-CR-20260823-01`。
- 功能上线后新合同填写的押金表示已实际收到；合同正式创建时，同一事务自动生成已确认押金收款和押金收取流水。
- 退租发起页、结算快照和应退押金继续读取押金流水最新余额，不直接读取合同的初始押金字段。
- 已有合同不补记押金；已有合同仅填写初始押金但没有押金流水时，退租押金余额仍为 0。
- 用户不填写押金收款日期、收款方式或凭证；系统记录合同创建日期和“系统自动入账”。

### 联动验收步骤

1. 新建一份押金为 10,000.00 元的测试专用合同并正式创建。
2. 核对只生成一笔“已确认”的押金收款和一笔“收取”的押金流水，当前余额均为 10,000.00 元。
3. 发起该合同退租，核对发起页财务快照和结算页押金余额均为 10,000.00 元。
4. 完成押金抵扣或退款后，核对最新流水余额、退租可退金额和财务中心“押金余额总额”同步减少。
5. 选择一份功能上线前已有且没有押金流水的合同，核对系统没有因其合同押金字段自动生成历史收款。

完整实现与自动化结果见 `docs/contract-deposit-auto-receipt-acceptance.md`。

## 金额展示与旧工单兼容修复（2026-08-23）

- 草稿、待确认和已驳回结算单尚未锁定金额，结算页不再把数据库初始值 `0.00` 当作正式结果展示，统一标记为“待计算 / 确认结算后计算”。
- 对变更 `SRMS-RB-1.0-CR-20260823-01` 生效前的既有合同，合同约定押金仍仅表示应收金额；退租应退押金严格以 `deposit_transactions` 实际押金余额流水为准。变更生效后的新合同按“填写押金即视为已收”处理。
- 增加一次性兼容迁移：仅修复补收功能上线前已经确认、合同仍处于待退租、最终应补收大于零且新增补收字段仍为初始值的旧工单；欠租按关联账单当前未收余额对账，避免审批后已收款被重复收取，并为旧验房扣款补建唯一补收账单。
- 本机测试环境已验证：登记 1400.00 元实际押金后，结算确认结果为应退押金 1400.00 元、待补收 0.00 元；旧工单补收 100.00 元后余额回到 0.00 元，并可完成退租、结束合同。
