# 退租补收单设计

## 背景与目标

SRMS 现有退租结算会计算 `finalReceivable`（待补收金额）。当欠租或验房扣款超过可抵扣押金时，系统必须先收清该金额，才可以结束合同和释放房源。

本设计采用“退租补收单 + 既有收款管理”方案：确认退租结算时生成不可重复的补收单；管理员通过既有收款登记完成收取；补收未结清时不允许最终完成退租。

本设计落实冻结规则“欠租、预收款和押金全部处理完成后，退款完成，合同结束”，不改变既有租金、押金、预收款、退款及验房扣款金额口径。

## 范围

包含：

- 对已确认且待补收金额大于零的退租结算生成补收单；
- 补收单通过现有收款与收款分配链路收取，支持部分收款；
- 在退租最终确认前强制校验补收单已收清；
- 在收款管理、租金账单和退租详情中展示中文来源、构成、余额与跳转入口；
- 后端权限、并发保护、审计及自动化测试。

不包含：

- 强制关闭合同；
- 修改已完成或已取消的历史退租记录；
- 将验房扣款计入租金收入；
- 新建第二套独立收款主表或绕过现有收款审批/分配规则。

## 数据模型

### 补收单承载方式

复用 `RentBill`、`Payment` 与 `PaymentAllocation`，为 `RentBill` 增加账单类别：

- `RENT`：现有租金账单，默认值；
- `CHECKOUT_SUPPLEMENTAL`：退租补收单。

为 `RentBill` 增加可空且唯一的 `checkoutSettlementId`，仅 `CHECKOUT_SUPPLEMENTAL` 使用。该关联保证一张退租结算单最多存在一张补收单。

补收单金额字段继续使用既有 `payableAmount`、`receivedAmount`、`outstandingAmount` 和状态字段，因此收款登记、部分付款、收据、退款/作废回退以及支付分配规则保持单一来源。

补收单的账期日期统一使用实际退房日，账单名称和来源展示为“退租补收”。为保持每合同账期序号唯一，补收单使用该合同现有最大账期序号加一；页面不把该序号解释为自然租赁月份。

### 金额构成与不可变快照

补收单保存两个不可变快照字段：

- `checkoutArrearsAmount`：实际退房日前有效租金账单的未收欠租；
- `checkoutInspectionChargeAmount`：维修、损坏、清洁、其他验房扣款合计。

两者之和必须等于退租结算确认时锁定的 `finalReceivable`，并等于补收单应收金额。确认后不得由收款页面改写。

`CHECKOUT_SUPPLEMENTAL` 不计入租金净应收、租金收入、收租率分子或分母；财务与驾驶舱查询须按账单类别过滤。它可在收款金额、退租补收和资金流水中单独统计。

## 生命周期

1. 管理员发起退租并提交结算草稿；既有流程不变。
2. 超级管理员确认结算时：
   - 计算并锁定押金抵扣、应退金额与待补收金额；
   - 当 `finalReceivable = 0` 时，不创建补收单；
   - 当 `finalReceivable > 0` 时，在同一事务创建一张 `CHECKOUT_SUPPLEMENTAL` 补收单及两类金额快照。
3. 合同与房源继续为“待退租”。补收单状态为“待收款”或“部分收款”时，不允许零额最终确认、押金退款最终确认或结束合同。
4. 管理员或超级管理员在收款管理登记补收单收款；允许分次收款，金额不得超过当前未收余额，也不得转入预收款。
5. 收清后补收单状态变为“已收清”。如同时存在应退押金或预收款，继续按既有退款登记与审批完成退租；如退款合计为零，超级管理员可点击“最终确认并完成退租”。
6. 最终确认的同一事务必须校验：退租结算已确认、合同和房源仍为待退租、补收单不存在或已收清、应退金额与退款记录一致。通过后才结束合同、更新房态和写入房态历史。

已确认的退租结算及其补收单禁止取消，防止回滚已发生的收款、抵扣或退款流水。

## 页面与交互

### 押金退还确认

已确认结算显示三种互斥状态：

1. **待补收**：展示欠租、验房扣款、补收合计、已收和未收；提供“前往收款登记”按钮，不显示完成退租按钮。
2. **待退款**：展示既有合并退款登记与审批流程；补收单必须已收清。
3. **可完成**：仅当补收为零或已收清，且退款合计为零时，向超级管理员显示“最终确认并完成退租”。

点击“前往收款登记”跳转至收款管理，自动带入合同和补收单；普通管理员可登记，超级管理员可登记并最终完成退租。

### 收款管理与租金账单

- 补收单以中文“退租补收”标签展示，不以“第 N 期租金”误导用户；
- 可按合同编号、楼栋房号、租户姓名搜索；
- 收款金额默认采用该补收单未收余额，允许手工填写较小金额；
- 大于未收余额、将余额转为预收款、将补收款分配给其他账单，均由后端拒绝；
- 账单详情显示“欠租 / 验房扣款”金额构成及关联退租结算单；
- 已退租合同只读详情显示补收金额构成、收款记录与收清时间。

## 权限与安全

- `ADMIN`、`SUPER_ADMIN`：查看补收单、登记收款；
- `SUPER_ADMIN`：确认结算、确认退款、零额最终确认、结束合同；
- `VISITOR`：仅继承既有只读边界，不得登记补收、确认结算或完成退租；
- 所有金额、账单类别、结算关联、余额和合同状态均由后端校验；前端隐藏按钮不构成权限控制；
- 使用数据库事务与条件更新避免并发重复收款、重复生成补收单或重复完成退租。

## 错误处理

错误提示统一中文：

- “退租补收款尚未收清，暂不能完成退租”；
- “本次补收金额不得超过未收余额”；
- “退租补收款不得转入预收款”；
- “补收单状态已变化，请刷新后重试”；
- “补收金额与退租结算锁定金额不一致”。

## 兼容与迁移

- 所有已有 `RentBill` 迁移为默认类别 `RENT`；
- 不回填、不生成历史补收单；
- 已完成、已取消或已确认的历史退租结算保持原数据和状态；
- 仅后续新确认的、`finalReceivable > 0` 的退租结算生成补收单。

## 验收与测试

- 无待补收的既有零额退租与退款退租全量回归；
- 欠租补收、验房扣款补收、两者合并补收均能生成正确金额快照；
- 一次性收清、分次收清、超额收款、收款作废/退款后的余额回退；
- 未收清时拒绝最终确认，收清后允许超级管理员最终确认；
- 管理员可登记但不能最终确认，游客写操作被后端拒绝；
- 补收单不进入租金收入、租金净应收和收租率统计；
- 并发收款、重复确认结算、重复最终确认和状态漂移均被拒绝；
- 收款管理、账单详情、退租详情和已退租合同查询显示中文来源与金额构成。

## 数据一致性修正（2026-08-22，优先于本文此前相冲突描述）

经实现前复核，不能把“欠租 + 验房扣款”总额复制为一张普通租金账单：这会使原欠租账单在补收后仍显示未收，造成重复记账。

因此，用户可见的“退租补收单”由退租结算单承载并锁定金额构成。欠租部分仍核销实际原租金账单；只有押金抵扣后剩余的验房扣款创建 `CHECKOUT_SUPPLEMENTAL` 专用账单。补收登记固定按原欠租优先、验房扣款随后分配。专用账单和对应收款在资金流水中显示为“退租补收”，不计入租金净应收、租金收入或租金收缴率。

新补收流程的最终确认和退款审批均以实时 `supplementalOutstandingAmount` 是否清零为准；为保证历史记录兼容，未启用补收流程的历史结算仍以既有 `finalReceivable` 校验。
