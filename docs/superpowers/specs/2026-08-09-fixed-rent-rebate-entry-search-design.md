# 固定月租退差入口与合同搜索设计

日期：2026-08-09
状态：已确认
业务基线：SRMS-RB-1.0，以及已确认的固定合同管理需求变更

## 1. 目标

在不改变固定月租退差金额、审批、凭证和权限规则的前提下，缩短从合同详情发起退差的操作路径，并让用户能够在固定月租退差页面快速找到符合条件的合同。

## 2. 范围

本次仅实现：

- 合同详情页根据退差资格显示或隐藏“固定月租退差”入口。
- 从合同详情进入退差页时，自动带入当前合同及其房源。
- 固定月租退差页增加合同搜索。
- 补充前端自动化测试和构建验证。

本次不实现：

- 不修改退差金额口径、结算方式、退款凭证或审批流程。
- 不扩大可退差合同状态。
- 不新增房源级退差记录；退差仍归属于合同，房源信息由合同关联得到。
- 不修改后端权限和数据结构。

## 3. 退差资格

合同必须同时满足以下条件：

- 合同状态为“履行中”（`ACTIVE`）。
- 计价方式为“固定月租”（`FIXED`）。

合同详情页和固定月租退差页必须使用同一资格判断：

- 符合条件：显示“固定月租退差”入口并允许进入退差表单。
- 不符合条件：合同详情页隐藏入口；退差合同搜索结果中不展示该合同。
- 前端提交服务保留资格校验，后端继续执行现有强制校验。

## 4. 合同详情页交互

- 用户在合同详情页点击“固定月租退差”。
- 合同工作区切换到“固定月租退差”页签。
- 当前合同自动成为已选合同，退差页展示该合同的合同编号、楼栋房号、租户和账单。
- 地址栏同步为 `contracts?tab=fixed-rebate&contractId=<合同编号>`，刷新或复制地址后仍能恢复当前退差上下文。
- 若合同状态或计价方式在跳转前发生变化，退差页不得显示可提交表单，并提示重新选择符合条件的合同。

## 5. 合同搜索交互

固定月租退差页顶部常驻合同搜索框，已选择合同后也可以继续搜索并切换合同。

搜索范围：

- 合同编号。
- 楼栋房号。
- 主租户姓名。

搜索规则：

- 对输入内容去除首尾空格。
- 使用不区分英文字母大小写的包含匹配。
- 只在“履行中 + 固定月租”合同集合中搜索。
- 搜索结果显示合同编号、楼栋房号和主租户姓名。
- 点击搜索结果后切换到对应合同，并同步地址栏中的 `contractId`。
- 无匹配结果时显示“未找到符合退差条件的合同”。
- 清空搜索词后恢复全部符合条件的合同。

当前合同列表接口已返回合同、房源和主租户信息，且未分页，因此本次使用前端本地搜索，不新增后端搜索接口。

## 6. 页面状态与错误处理

- 无符合条件合同：显示空状态，不展示退差表单。
- 有符合条件合同但尚未选择：显示搜索和选择引导。
- 地址栏合同不存在或不符合资格：不自动选中，不展示退差表单，并显示明确提示。
- 合同详情加载失败、账单加载失败或退差提交失败：沿用现有中文错误提示，不改变后端错误信息映射。

## 7. 权限与安全

- 不改变现有管理员提交、超级管理员确认的权限规则。
- 搜索结果仅来自当前用户已有权限访问的合同列表。
- 前端隐藏入口不是权限控制；后端现有退差接口继续强制校验身份、角色、合同状态和计价方式。

## 8. 自动化测试

至少覆盖：

- “履行中 + 固定月租”合同详情显示入口。
- 待开始、待退租、已终止、已到期、已作废合同隐藏入口。
- 非固定月租合同隐藏入口。
- 点击详情入口携带当前合同编号进入退差页。
- 刷新带 `tab=fixed-rebate&contractId=` 的地址能够恢复合同。
- 合同编号、楼栋房号、租户姓名三种搜索均能命中。
- 不符合资格的合同不会出现在搜索结果。
- 无结果和清空搜索的页面状态正确。
- 现有退差提交资格与后端强制校验不被削弱。

## 9. 验收标准

- 用户从符合资格的合同详情点击一次即可进入该合同退差表单。
- 不符合资格的合同详情看不到退差入口。
- 用户可按合同编号、楼栋房号、租户姓名找到任意符合资格的合同。
- 搜索和详情跳转不会把不符合资格的合同带入可提交状态。
- 前端测试、构建和项目 Lint 全部通过。
