# 收款详情记录局部分页设计

## 目标

当收款记录较多时，仅对收款详情页左侧“收款记录”区域分页，避免整页过长，并减少一次性查询的数据量。

## 已确认方案

- 采用后端真实分页，不在浏览器中一次加载全部记录后切片。
- 左侧列表固定每页 10 条，不提供每页条数选择。
- 标题显示“收款记录（共 N 笔）”。
- 分页器位于左侧列表底部，仅提供上一页、页码和下一页。
- 查询条件变化并点击“查询”后回到第 1 页。
- 翻页只更新左侧记录列表；右侧当前已打开的收款详情保持不变。
- 没有记录时继续显示现有空状态。
- 不改变现有收款权限、查询条件、收款详情数据或业务状态。

## 接口

`GET /api/payments` 增加 `page`、`pageSize` 查询参数，默认分别为 `1`、`10`，返回：

```ts
{
  items: PaymentListItem[]
  page: number
  pageSize: number
  total: number
}
```

服务端继续应用原有搜索条件和权限脱敏规则，在同一筛选条件下执行总数统计和当前页查询。

## 验收

- 默认只请求并显示第 1 页的 10 条记录。
- 总数大于 10 时可在左侧切换页码。
- 切换页码后右侧已打开详情不消失。
- 查询后页码回到 1。
- 后端正确使用 `skip`、`take` 并返回总数。
