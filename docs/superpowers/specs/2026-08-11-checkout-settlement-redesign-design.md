# 退租结算重设计

## 目标与范围

以 `srms-checkout-workflow-prototype.html` 为视觉、布局和交互参考，重做退租结算工作区。页面使用现有系统侧边栏与顶部导航，并提供原型同款的三项顶部页签：发起退租、退租结算、押金退还确认。

本次同时确认一项正式业务变更：确认结算不再直接结束合同或释放房源；必须经过最终退款确认（或零额最终确认）才可完成退租。

不提前扩展与退租无关的功能，不删除历史结算、退款、押金、预收款或账单数据。

## 角色与权限

- `ADMIN`、`SUPER_ADMIN`：发起退租、维护草稿结算项目、提交结算、登记合并退款。
- `SUPER_ADMIN`：确认或驳回结算；确认最终退款或零额最终确认；结束合同并释放房源。
- 后端继续强制校验权限，前端隐藏不替代后端授权。

## 页面与交互

### 全局结构

- 保留当前系统侧边栏、顶部导航和中文日期选择器。
- 内容区采用原型的浅灰背景、白色卡片、蓝色主操作、红色必填星号、12px 标签、14px 正文、22px 页面标题。
- 顶部使用可分享的三项胶囊页签：`发起退租`、`退租结算`、`押金退还确认`。
- 桌面端使用左内容/右摘要两栏；窄屏降为单栏，页签横向滚动，主要操作按钮最小高度 40px。

### 1. 发起退租

- 只列出可发起退租的履行中合同。
- 必填：合同、退租类型、计划退房日期、房屋交接日期、验房日期、退租后房态、退租原因。
- 右侧显示只读财务快照：押金余额、当前欠租、预收款余额、未来账单数量。
- 提交成功后创建草稿结算单，将合同与房源状态变为待退房；不得提前作废未来账单或结束合同。

### 2. 退租结算

- 顶部显示结算单状态横幅、合同/房源/承租人信息和四步流程：发起退租、房屋验收、结算确认、退款结束。
- 展示实际退房日期、交接日期、验房日期、退房后房态和验房备注。
- 结算项目表支持欠租、维修、损坏、清洁、其他扣款；欠租必须关联有效账单且金额不得超过未收金额，其他扣款必须填写验收依据。
- 结算汇总展示押金余额、欠租抵扣、其他扣款、预收款应退、租客仍需补交、押金应退和退款合计。
- 提交结算后进入待确认；超级管理员确认结算时锁定金额，并只作废实际退房日之后、未收款的未来账单。
- 确认结算后，合同和房源继续保持待退房；不得自动结束。

### 3. 押金退还确认

- 对已确认结算单显示结束条件核验、退款信息、退款后的系统处理和提交/审批信息。
- 合并退款金额固定为：`押金应退 + 预收款应退`，前端只读展示组成与合计；不得手工改写金额。
- 合计大于 0：管理员必须填写退款日期、退款方式并上传至少一份凭证后提交。确认后锁定凭证，写入押金退款流水和预收款退款流水。
- 合计等于 0：显示“无需退款确认”，不要求退款方式或凭证；超级管理员执行“确认结算完成”。
- 最终确认成功后，结算单标记完成、合同结束、房源更新为结算单指定房态，并写入房态历史。

## 后端生命周期与账务

1. `ACTIVE` 合同发起退租后变为 `PENDING_CHECKOUT`，房源同样变为待退房，结算单为 `DRAFT`。
2. 草稿结算提交后为 `PENDING`；超级管理员确认后为 `APPROVED`，未来未收账单作废，但合同和房源保持待退房。
3. 若退款合计大于 0，登记一笔退款申请。其总额必须等于结算单的 `depositRefundableAmount + prepaymentRefundableAmount`。
4. 确认合并退款时，按结算单快照拆分：
   - 对押金部分创建 `DepositTransaction(REFUND)`，余额归零；
   - 对预收款部分创建 `PrepaymentTransaction(REFUND)`，余额归零；
   - 锁定退款凭证，更新退款/结算/合同/房源及历史。
5. 若退款合计为 0，超级管理员调用独立的零额最终确认接口；该接口重新校验结算已确认、合同和房源待退房、应补金额为 0、两类应退金额均为 0，之后结束合同和释放房源。
6. 任一最终确认都必须在单一数据库事务内完成，重复确认或状态漂移必须拒绝。

## 数据与兼容性

- 不新增第二套退租或退款主表；保留现有 `CheckoutSettlement`、`DepositRefund`、`DepositTransaction`、`PrepaymentTransaction` 和附件关联。
- 将现有退款申请的 `refundAmount` 定义为合并退款总额；各组成金额由已锁定的结算单快照派生，不依赖可编辑前端输入。
- 现有已完成结算/退款不回填、不删除、不改变历史金额。
- 需要为现有退款 DTO、服务和接口扩展“合并退款”校验及零额最终确认端点；如数据库字段无法表达审计所需来源，再以最小 migration 增加不可变拆分金额字段。

## 错误处理

- 所有提交、确认、驳回操作显示后端返回的具体中文原因。
- 后端拒绝：非草稿提交、非待审批确认、非超级管理员确认、账单/验收依据不完整、金额不等于锁定结算额、重复退款、退款凭证无效、状态漂移。
- 不通过前端隐藏来绕过权限或金额校验。

## 验收与测试

- 前端：三页签导航、必填红星、中文日期、响应式布局、角色按钮、错误提示、退款合计只读和零额确认状态。
- 后端单元/接口：发起退租、结算项目校验、确认结算不结束合同、合并退款金额及拆分流水、零额最终确认、凭证锁定、重复确认与权限拒绝、事务回滚。
