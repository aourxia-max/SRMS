# 驾驶舱本月新增租房与实际退租指标设计

日期：2026-08-04

## 目标

在驾驶舱“本月租金收缴概览”中增加“本月新增租房数量”和“本月退租数量”，并将该概览移动到“楼栋房态图”上方。指标用于快速判断本月租赁流入与实际退租情况，不改变冻结的合同、退租、金额、权限或状态规则。

## 统计口径

### 本月新增租房数量

- 统计合同开始日期落在当前自然月内的已确认合同。
- 排除 `DRAFT` 草稿合同。
- 包含当前为 `PENDING_START`、`ACTIVE`、`PENDING_CHECKOUT`、`ENDED` 或 `TERMINATED` 的合同，确保本月开始后又提前退租的真实租赁仍被计入。
- 一个合同计为一次新增租房。

### 本月退租数量

- 仅统计状态为 `COMPLETED` 的退租结算。
- 以退租结算的 `actualCheckoutDate`（实际退租日期）是否落在当前自然月内为准。
- 正常到期退租与提前退租采用相同口径。
- 草稿、待确认、已驳回、仅批准但未完成的退租结算不计入。
- 一个已完成退租结算计为一次退租。

## 筛选与权限

- 两个指标跟随驾驶舱顶部的楼栋筛选。
- 未选择楼栋时统计全部楼栋。
- 两个指标不含个人资料或金额，所有可访问驾驶舱的已登录角色均可查看。
- 原租金金额、欠租金额和收缴率仍保持当前权限：仅超级管理员查看。

## 后端设计

- 沿用现有 `GET /api/dashboard`，不增加独立接口。
- 在驾驶舱服务中使用当前自然月起止时间和可选 `buildingId` 进行数据库聚合计数。
- 响应新增：
  - `monthlyMoveInCount`
  - `monthlyCheckoutCount`
- 统计与现有租金概览并行执行，避免增加不必要的串行等待。
- 不返回合同、租户或退租明细，减少数据暴露。

## 前端设计

- 将完整“本月租金收缴概览”卡片移动至左侧内容栈顶部，紧邻驾驶舱基础指标之后、楼栋房态图之前。
- 超级管理员视图在原四个金额指标旁增加两个数量指标：
  - 本月新增租房
  - 本月实际退租
- 非超级管理员视图显示原有待收提醒、逾期欠租笔数以及两个新增数量指标，继续隐藏金额和收缴率。
- 六项指标在宽屏下保持高信息密度排列；中小屏自动换行，避免文字和数字挤压。
- 两个数量指标均显示“X 套/次”中的数字与简短说明，不新增跳转或复杂交互。

## 异常与边界

- 没有符合记录时显示 `0`。
- `actualCheckoutDate` 为空的退租结算不计入。
- 月份以服务器当前时区及现有自然月工具为基准。
- 楼栋筛选通过合同关联房源或退租结算关联合同与房源完成，不依赖前端二次计算。

## 测试与验收

- 后端单元测试覆盖：月初/月末边界、草稿合同排除、提前退租、未完成退租排除、实际退租日期为空、楼栋筛选。
- 接口测试确认新字段存在且不返回新增敏感明细。
- 前端构建验证布局调整、超级管理员与普通角色展示分支。
- 在本地 `srms_test` 环境重新构建 API 与 Web，并人工确认概览位于楼栋房态图上方。

## 不在本次范围

- 不增加入住确认流程或入住时间字段。
- 不修改合同生命周期、退租审批、退款或房态变更规则。
- 不增加趋势图、同比环比或指标详情页面。
- 不修改线上环境，除非用户后续明确要求部署。
