# E2E 数据隔离与测试库防污染设计

## 背景

当前部分真实 MySQL E2E 直接连接日常页面验收使用的 `srms_docker`。合同纠错和并发审批测试为了保留审计链来源，会留下楼栋、房源、合同、账单、收款和退租记录。另有部分测试未显式加载测试配置时，会回退到 `backend/.env`，存在误连本机开发库的风险。

## 目标

- 真实数据库 E2E 不再修改日常测试环境 `srms_docker`。
- E2E 不得连接 `localhost:3306/srms`、生产库或任何远程数据库。
- 每次运行使用全新的临时数据库，测试成功或失败后都删除。
- 测试自行准备超级管理员和普通管理员，不依赖共享库基础账号。
- 保留合同纠错、审计链、并发审批、退租退款和财务汇总的真实 MySQL 覆盖。
- 修复“撤销已完成退租”相关代码的 ESLint 和 Prettier 错误。

## 非目标

- 本次不删除或修复 `srms_docker` 中已有的历史 E2E 残留。
- 本次不访问、迁移或修改正式环境数据库。
- 本次不清理可能存在于 `localhost:3306/srms` 的历史测试残留。
- 本次不改变合同、收款、退款、退租或财务统计的生产业务规则。

## 方案

### 统一临时数据库运行器

新增测试专用运行器。运行器只读取 `deploy/.env.test` 中连接本机测试 MySQL 所需的配置，不显示、记录或提交密码。它只允许连接 `127.0.0.1`、`localhost` 或 `::1`，端口必须是 `13306`，源库必须是 `srms_docker`。

运行器生成唯一的临时库名：

```text
srms_e2e_<日期时间>_<随机后缀>
```

数据库名必须满足 `^srms_e2e_[a-z0-9_]+$`。创建、使用和删除数据库前都执行相同的主机、端口和名称校验。

### 生命周期

1. 读取并校验 `deploy/.env.test`，不输出敏感值。
2. 连接本机 `127.0.0.1:13306` 的 MySQL 管理端。
3. 创建唯一临时数据库，字符集使用 `utf8mb4`。
4. 将进程 `DATABASE_URL` 指向临时数据库。
5. 执行 `prisma migrate deploy`，保证结构与当前代码一致。
6. 创建测试专用超级管理员和普通管理员；密码字段使用不可登录的测试占位哈希，接口测试继续通过覆盖认证守卫注入身份。
7. 串行运行真实 MySQL E2E。
8. 在 `finally` 中关闭应用和数据库连接，再删除本次临时数据库。
9. 删除后反查 `information_schema.schemata`，必须确认临时库不存在；清理失败时测试命令返回失败。

### 双重安全门槛

- 运行器层：只允许本机 `13306` 和 `srms_e2e_*` 目标。
- 测试层：真实写库套件启动时再次校验 `DATABASE_URL`，拒绝 `srms_docker`、`srms`、空库名、大小写不合规库名和远程主机。

任何门槛不满足时，在创建业务数据前立即以中文错误退出。

### 测试账号

运行器统一创建：

- 一个状态为 `ACTIVE` 的 `SUPER_ADMIN`；
- 一个状态为 `ACTIVE` 的 `ADMIN`。

物业办事 E2E 改为使用这些专用账号，不再要求共享测试库预先存在普通管理员。测试结束时无需逐条删除账号，因为整个临时数据库会被删除。

### 现有 E2E 调整

- 删除各测试文件中重复的 `.env.test` 解析函数，统一使用测试支持模块。
- `contract-deposit.e2e-spec.ts` 不再有机会回退到 `backend/.env`。
- `contract-void-correction.e2e-spec.ts` 可以继续保留已完成审计场景，因为只存在于临时库。
- `contract-void-executor.mysql.e2e-spec.ts` 可以继续验证真实审计链尾部，不再污染共享库。
- `property-affairs.e2e-spec.ts` 使用运行器创建的两种角色账号。
- 纯授权和纯内存 E2E 可以继续运行，但完整数据库回归统一由临时库运行器入口启动。

## 错误处理

- 创建临时库失败：不启动 Jest，返回中文错误。
- 迁移失败：进入清理阶段，删除已创建临时库，命令返回失败。
- 测试失败：保留测试输出，随后删除临时库，命令仍返回原测试失败码。
- 删除失败：命令返回失败并仅显示临时库名，不显示连接凭据。
- 发现目标不是本机 `13306` 或库名不合规：立即拒绝，绝不执行 `CREATE DATABASE` 或 `DROP DATABASE`。

## 验证

### 安全门槛单元测试

- 接受本机 `13306/srms_e2e_*`。
- 拒绝共享库 `srms_docker`。
- 拒绝开发库 `srms`。
- 拒绝远程主机、其他端口、空库名、非法字符和大小写不合规库名。
- 验证创建和删除都调用同一安全校验。

### 生命周期测试

- 迁移前失败也会删除已创建临时库。
- Jest 失败仍执行删除并保留失败退出码。
- 删除失败使整个命令失败。
- 运行前后 `srms_docker` 的核心表数量和财务汇总完全一致。
- 运行后 `information_schema.schemata` 中不存在本轮 `srms_e2e_*`。

### 项目回归

- 后端单元测试、E2E、构建和 `lint:check`。
- 前端单元测试和构建。
- 测试环境 API、Web 健康检查。
- 账单公式、实收/未收、退款拆分、押金/预收余额链、房源占用和退租状态一致性 SQL。

## 数据安全

- 允许创建和删除的唯一数据库范围：本机 `127.0.0.1:13306` 上名称匹配 `srms_e2e_*` 的临时数据库。
- `srms_docker` 只允许在测试前后做只读快照比对。
- 不打印、复制或提交 `deploy/.env.test` 中的密码和密钥。
- 不连接正式环境，不对其他数据库执行迁移、写入或删除。
- 公共 E2E 收到可捕获的 SIGINT/SIGTERM 时，先停止并等待迁移或 Jest 子进程，再删除并确认临时库不存在，最终分别返回 130/143。SIGKILL、操作系统强制终止和断电无法捕获，无法保证进程内清理执行。
