# 房源详情页编辑设计

## 范围

在房源详情页增加房源基础信息编辑能力，复用现有房源更新接口和权限模型，不新增数据库字段，不改变合同、收款或房态历史流程。

## 用户体验

- 详情页右上角显示“编辑房源”；仅 `ADMIN` 与 `SUPER_ADMIN` 可见。
- 点击后打开编辑弹窗，预填当前房源资料。
- 可编辑字段：房号、楼层、面积、房源类型、装修状态、使用用途、业主姓名、业主电话、业主备注、房源备注。
- 房态不放入编辑弹窗，继续通过现有房态变更流程维护，以保证状态历史记录完整。
- 保存成功后关闭弹窗并重新加载详情；失败时保留弹窗内容并提示错误。
- 普通用户仍可查看详情，但不能看到编辑入口，也不能通过接口修改。

## 数据流与权限

前端提交 `PATCH /api/properties/rooms/:id`，后端 `JwtAuthGuard` 与 `RolesGuard` 强制要求管理员或超级管理员。后端沿用现有 DTO 校验、楼栋变更时的完整房号重算和唯一性约束。

## 测试

- 后端控制器测试：详情更新请求转发正确；管理员更新成功；权限由守卫配置覆盖。
- 前端构建与类型检查通过。
- 线上手工验收：管理员打开详情、修改并保存；普通用户仅查看。

## 非目标

- 不修改 Prisma schema 或迁移。
- 不增加房态修改入口。
- 不编辑合同、租户、财务和收款信息。
