# 新增合同表单同步循环修复设计

## 背景

测试环境的“新增合同”页面在选择房源后出现页面卡死。房源、租户和合同接口均成功返回，后端日志没有异常，问题发生在前端组件状态同步阶段。

## 根因

`ContractFormPanel.vue` 同时存在两组深度监听：

1. 父组件 `modelValue` 变化时，将完整表单复制到子组件本地表单。
2. 子组件本地表单变化时，将完整表单复制并发送回父组件。

选择房源后，子组件发送新对象给父组件；父组件再把新对象传回子组件。由于每次复制都会创建新的数组和对象，两侧持续认为表单发生变化，形成无限反馈循环并导致浏览器卡死。

## 同类问题审计

扫描 `frontend/src` 下全部 Vue 与 TypeScript 文件后，仅 `ContractFormPanel.vue` 存在成对的深度监听和 `update:modelValue` 完整对象写回。

- `ContractTopNav.vue` 只在用户点击时发送页签值，不存在深度监听。
- 其他表单和页面没有发现相同的父子双向深度写回结构。

因此本次只修复已确认的合同表单循环，不做无关重构。

## 方案比较

### 方案一：内容相同则跳过同步（采用）

在父传子和子传父两条同步路径上比较规范化后的表单快照。只有内容真正变化时才写回或发送事件。

优点：

- 修改范围最小。
- 保留现有表单结构和 Element Plus 校验。
- 恢复草稿、路由带入房源和父页面重置仍能工作。
- 可以通过组件测试直接验证不会重复发送。

### 方案二：将表单状态全部提升到父组件

删除子组件本地表单，让所有字段直接修改父组件状态。

优点是状态来源单一；缺点是需要大范围调整表单校验、附件、优惠和提成字段，超出本次故障修复范围。

### 方案三：使用临时锁或计数限制监听

写回时设置布尔锁，或限制短时间内的更新次数。

该方案依赖时序，异步更新和父页面重置可能绕过锁，不作为正式修复。

## 详细设计

1. 为 `ContractFormModel` 生成稳定的内容快照。
2. 父组件传入的表单与子组件当前表单内容相同时，不执行 `Object.assign`。
3. 子组件变化后的内容与最近一次已发送内容相同时，不重复发送 `update:modelValue`。
4. 当父组件真实改变表单，例如新建、恢复草稿或带入房源时，子组件仍更新本地表单，并同步更新最近快照。
5. 不改变合同字段、接口载荷、权限、账单计算或数据库结构。

## 自动化测试

新增组件级回归测试：

1. 父组件使用真实 `v-model` 挂载合同表单后，选择房源不会形成无限更新。
2. 一次房源选择只产生一次有效父表单变化，`roomId` 正确保留。
3. 父组件主动重置为空表单后，子组件显示的新值同步更新。
4. 父组件恢复包含房源的草稿后，子组件正确显示房源。
5. 现有合同工作区测试、前端全量测试和生产构建继续通过。

## 验收标准

- 测试环境选择任意房源后页面不再卡死。
- 可以继续选择主承租人、日期和租金等字段。
- 取消后重新新增、恢复草稿和从房源页进入新增合同均正常。
- 全前端同类模式扫描无新增命中。
- 不修改后端和数据库。
