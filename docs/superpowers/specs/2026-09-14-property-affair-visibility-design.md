# 物业办事事项可见范围设计

日期：2026-09-14  
状态：已确认，待实施

## 1. 目标

在现有“物业办事”模块中增加事项级可见范围控制。事项默认对所有有权进入物业办事模块的用户可见；创建或编辑事项时，可以改为仅指定人员可见。超级管理员始终可以查看全部事项。

本次只控制事项能否被用户发现和访问，不新增只读角色，也不改变被授权用户原有的编辑、进度、附件和删除权限。

## 2. 权限规则

### 2.1 可见范围

每条物业办事事项具有以下一种可见范围：

- `ALL`：所有有权进入物业办事模块的用户可见，作为默认值。
- `RESTRICTED`：仅创建人、指定用户和超级管理员可见。

“所有人”沿用现有模块入口权限，不包含无权进入物业办事模块的游客。

### 2.2 系统兜底权限

- 事项创建人始终可见，即使没有出现在指定人员名单中。
- 所有超级管理员始终可见全部事项，不依赖指定人员名单。
- 被指定的普通管理员按现有权限操作，可以查看、编辑、追加进度、管理附件和删除。
- 未被授权的普通管理员不能在任何入口发现事项，也不能通过事项 ID 或附件地址绕过限制。

### 2.3 用户状态变化

- 指定人员候选项只包含当前有效的管理员和超级管理员，不包含游客和已停用用户。
- 指定用户停用后立即失去基于名单获得的访问权限。
- 创建人停用不改变数据归属；其重新启用后仍可按创建人兜底规则访问。
- 用户永久删除时自动解除其可见人员关联，不删除事项。

## 3. 数据设计

### 3.1 事项字段

为 `PropertyAffair` 增加可见范围字段 `visibilityScope`，取值为 `ALL` 或 `RESTRICTED`，默认值为 `ALL`。

### 3.2 指定人员关联

新增规范化关联表 `PropertyAffairViewer`：

- `affairId`：物业办事事项 ID。
- `userId`：被授权用户 ID。
- `createdAt`：授权记录创建时间。
- `(affairId, userId)` 建立唯一约束。
- 事项删除时级联删除关联；用户删除时解除关联。

不使用 JSON 保存用户 ID，确保外键完整性、检索性能和用户生命周期处理可靠。

### 3.3 历史数据

数据库迁移仅增加枚举、字段、关联表和必要索引。历史事项因字段默认值统一按 `ALL` 处理，不重算、不删除、不改写其他业务数据。

## 4. 页面交互

### 4.1 新增与编辑表单

- 增加“可见范围”单选项，默认选中“所有人可见”。
- 选择“指定人员可见”后显示支持输入、搜索和多选的人员选择框。
- 指定人员模式至少选择一名用户后才能保存；创建人不需要重复选择自己。
- 编辑时允许在两种可见范围之间切换，保存成功后立即生效。

### 4.2 详情页

- `ALL` 显示“所有人可见”。
- `RESTRICTED` 显示指定人员姓名。
- 页面不额外罗列因系统兜底规则获得权限的超级管理员和创建人。

## 5. 后台权限边界

后台提供统一的事项可见条件和单项访问校验，以下全部入口必须复用，不允许只由前端隐藏：

- 事项分页列表、搜索和筛选。
- 事项详情、新增后的返回、编辑、状态和进度操作。
- 删除、回收站列表、恢复和永久删除。
- 附件列表、上传、预览、下载和解除关联。
- 驾驶舱物业办事摘要。
- 房源、承租人和合同详情中的关联物业办事区域。

未授权用户直接访问事项或附件时，统一返回“事项不存在或无权查看”，避免泄露事项是否存在。超级管理员的永久删除等既有专属权限保持不变。

## 6. 接口与日志

- 新建和编辑接口接收 `visibilityScope` 与 `viewerUserIds`。
- `ALL` 模式忽略并清空指定人员关联。
- `RESTRICTED` 模式校验人员 ID 去重、用户存在、账号有效且角色为管理员或超级管理员。
- 列表和详情响应返回可见范围；只有有权查看事项的用户才会获得指定人员信息。
- 修改可见范围写入操作日志，记录操作人、操作时间，以及修改前后的范围和指定人员。
- 并发编辑继续使用现有 `version` 乐观锁，避免较旧页面覆盖最新可见范围。

## 7. 测试要求

### 7.1 单元与接口测试

- 新建事项未传可见范围时默认为所有人可见。
- 指定一人和指定多人时，名单内用户可以访问，名单外普通管理员不能访问。
- 创建人未在名单中仍可访问。
- 超级管理员未在名单中仍可访问。
- 无权限用户访问详情、附件和写操作时被拒绝。
- 从 `ALL` 改为 `RESTRICTED`、修改名单、再改回 `ALL` 后立即按新规则生效。
- 停用指定用户后立即失去访问权限。

### 7.2 全入口防泄露测试

使用至少三名普通管理员和一名超级管理员，覆盖：

- 事项列表、搜索、详情和回收站。
- 驾驶舱摘要。
- 房源、承租人和合同关联事项。
- 附件预览和下载。
- 编辑、进度、删除与恢复。

验证未授权事项不会出现在数量、列表或关联区域中，不能通过猜测 ID 访问。

### 7.3 发布顺序

1. 在隔离工作区实施并完成数据库、后台和前端测试。
2. 通过代码复审和完整回归后合并到本地 `main`。
3. 更新本机测试环境，供项目负责人使用真实页面验收。
4. 正式环境必须再次取得明确授权，并先完成数据库备份和校验后部署。

## 8. 不在本次范围

- 不新增“仅查看”或字段级权限。
- 不允许按游客或外部人员授权。
- 不建立跨模块通用权限中心。
- 不增加提醒、消息通知或审批流程。
- 不改变物业办事模块现有角色入口、状态、优先级和业务关联规则。
