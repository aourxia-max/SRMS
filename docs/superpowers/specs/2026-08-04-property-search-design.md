# 房源管理与首页房源搜索设计

日期：2026-08-04

## 目标

为房源管理页增加完整搜索功能，并在首页驾驶舱提供快速房源搜索入口。两个页面共用后端搜索规则，用户可以通过房号、业主/租户姓名或电话快速定位房源并进入详情。

## 搜索范围

关键词匹配以下字段：

- 完整房号 `fullHouseNo`，例如 `1栋601`。
- 单独房号 `houseNo`，例如 `601`。
- 业主/租户姓名 `ownerName`。
- 业主/租户电话 `ownerPhone`。

不匹配房源备注、业主/租户备注、装修状态或其他自由文本字段。关键词去除首尾空白；空关键词等同于未启用关键词搜索。

## 后端接口

扩展现有认证接口：

```text
GET /api/properties/rooms
```

支持可选查询参数：

- `keyword`：关键词，最长 100 个字符。
- `buildingId`：楼栋 ID，正整数。
- `status`：现有 `RoomStatus` 枚举值。
- `limit`：结果上限，1 至 20，仅首页快速搜索使用。

查询规则：

- 始终包含 `deletedAt: null`，已删除房源不能被搜索到。
- 关键词字段之间使用 OR；关键词与楼栋、房态条件之间使用 AND。
- 结果继续包含现有房源和楼栋信息，并使用当前楼栋、楼层、房号排序。
- 首页传入 `limit=8`；房源管理不传 `limit`，返回完整筛选结果。
- 所有请求继续经过 JWT 后端认证，不依赖前端隐藏。

## 房源管理页

- 在现有楼栋和房态筛选旁增加关键词输入框，提示文字为“搜索房号、姓名或电话”。
- 关键词输入采用约 300 毫秒防抖，避免每次按键立即发送请求。
- 关键词、楼栋和房态变化后均由后端重新查询，三个条件可叠加。
- 支持一键清空关键词。
- 数量文字显示当前结果数量，例如“找到 12 套房源”；楼栋总数保持现有显示。
- 页面从 `/properties?q=关键词` 打开时，自动恢复关键词并执行搜索。

## 首页驾驶舱

- 在驾驶舱页头操作区增加快速搜索输入框。
- 输入关键词后调用房源搜索接口，最多返回 8 条。
- 每条建议展示完整房号、楼栋、中文房态和业主/租户姓名。
- 不在建议项中展示电话号码；电话仅可作为匹配条件。
- 点击房源结果直接进入 `/properties/:id` 房源详情。
- 建议列表最后提供“查看全部结果”，跳转 `/properties?q=关键词`。
- 空关键词不请求后端，并立即清空建议列表。

## 状态与异常处理

- 请求失败时不覆盖当前房源列表；显示简短错误提示并允许重新输入或刷新。
- 快速搜索请求采用防抖，并忽略过期请求结果，避免快速输入时旧结果覆盖新结果。
- 无匹配结果时显示“未找到匹配房源”。
- 搜索不改变房源编辑、删除、房态修改或查看详情权限。

## 测试与验收

- DTO 测试：关键词长度、楼栋 ID、房态枚举和 `limit` 边界。
- 后端测试：四类关键词字段、OR 匹配、楼栋与房态组合 AND、空关键词、软删除排除、`limit=8`。
- 接口测试：未登录访问被拒绝；响应不新增与搜索无关的敏感字段。
- 前端构建验证：房源管理组合筛选、查询参数恢复、首页最多 8 条、查看详情与查看全部跳转。
- 本地 `srms_test` 环境人工验收房号、姓名和电话搜索。

## 不在本次范围

- 不搜索合同、租户档案、收款或财务记录。
- 不增加模糊拼音、同音字、分词、搜索历史或热门搜索。
- 不增加数据库全文索引或新数据表。
- 不部署线上环境，除非用户后续明确要求。
