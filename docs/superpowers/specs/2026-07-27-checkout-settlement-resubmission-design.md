# 退租结算驳回后重提设计

## 目标

让被超级管理员驳回的退租结算单可以由管理员在原单上补正后重新提交，避免合同停留在待退租状态却无法继续处理。

## 范围与不变项

- 仅处理 `REJECTED -> DRAFT -> PENDING` 的结算单修正闭环。
- 不新建结算单，不改变合同 `PENDING_CHECKOUT` 或房源 `PENDING_CHECKOUT` 状态。
- 不改变押金抵扣、欠租优先、验房扣款、退款、未来账单作废、金额计算或审批权限。
- 原驳回原因和第一次审批时间永久保留；再次提交更新提交人和提交时间，后续仍必须由超级管理员确认。

## 方案

新增受 JWT 与角色守卫保护的“退回草稿”接口。仅管理员或超级管理员可以将本合同的 `REJECTED` 结算单恢复为 `DRAFT`；接口不会删除结算项目，管理员可在原单中调整项目后通过既有提交接口再次进入 `PENDING`。

前端只对 `REJECTED` 结算单显示“退回草稿并修改”按钮。成功后加载原单已有项目到结算编辑区，避免用户重新录入全部内容；不为审批通过或完成的结算单提供该入口。

## 验收与测试

1. `REJECTED` 结算单可退回 `DRAFT`，既有项目与驳回原因仍保留。
2. `DRAFT`、`PENDING`、`APPROVED`、`COMPLETED` 结算单调用该接口均被拒绝。
3. 管理员可调用，游客不可调用；后端而非仅前端强制校验。
4. 回到草稿后重新提交，仍遵循既有欠租和验房扣款校验，并需要超级管理员再次确认。
