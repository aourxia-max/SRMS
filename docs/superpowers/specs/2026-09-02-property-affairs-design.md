# 物业办事功能设计

日期：2026-09-02  
状态：规格已确认，待实施

## 1. 背景与目标

物业日常会产生维修协调、住户沟通、证件办理、现场处理、外部单位对接等非合同、非收款事项。目前系统缺少统一记录入口，事项容易散落在聊天、纸张或个人记忆中。

本功能新增独立的“物业办事”模块，用于自由记录、持续跟进和查询物业办事事项，并能关联现有楼栋、房源、承租人和合同。

核心目标：

1. 主事项内容可持续补充和修改。
2. 办理进度独立追加，保留完整过程，不被主内容编辑覆盖。
3. 一个事项可以同时关联多个不同类型的业务对象。
4. 在驾驶舱及相关业务详情页中快速看到相关事项。
5. 通过回收站降低误删风险，通过权限和日志保留管理边界。

本模块不产生提醒，不涉及费用，不改变房态、合同状态或任何财务数据。

## 2. 已确认业务规则

### 2.1 状态

事项使用四种中文状态：

- `PENDING`：待办理
- `IN_PROGRESS`：办理中
- `COMPLETED`：已完成
- `CANCELLED`：已取消

状态流转规则：

- 新建事项默认进入“待办理”。
- 待办理可转为办理中、已完成或已取消。
- 办理中可转为已完成或已取消。
- 已完成事项可重新开启为办理中。
- 已取消事项保留记录；如需继续处理，可重新开启为办理中。
- 每次状态变化均追加一条系统进度记录，并写入操作日志。
- 完成时记录完成时间；重新开启时不删除历史完成时间和完成记录，当前主记录的完成时间恢复为空。

### 2.2 分类和优先级

- 分类不是必填项。
- 分类可以直接输入，也可以选择历史已使用分类。
- 新输入的分类保存后自动成为后续候选项，不单独建设分类管理页面。
- 优先级固定为：普通、重要、紧急。
- 列表和详情用稳定、易区分的颜色标签展示优先级，并支持筛选。

### 2.3 负责人和外部联系人

- 可选择一个系统内部用户作为负责人。
- 可填写外部办理人或外部单位名称、联系电话和其他联系方式。
- 内部负责人和外部联系信息可以同时存在，也允许根据实际情况只填写其中一类。
- 内部负责人只用于记录和筛选，不产生提醒或待办推送。

### 2.4 关联业务对象

- 一个事项可以关联零个或多个楼栋、房源、承租人和合同。
- 四种对象可以混合关联，例如同一事项同时关联 1 栋、1栋101、张三和对应合同。
- 保存前由后端校验所有关联对象真实存在；任一关联无效时整次保存失败，避免只保存一部分关系。
- 房源、承租人、合同详情页反向展示未删除的相关事项。
- 关联对象后续停用、结束或软删除时，不删除物业事项；事项详情保留关联对象当时的显示信息，并标注“已失效”或对应当前状态。

### 2.5 附件

- 事项级附件支持图片、PDF、Word 和 Excel。
- 图片和 PDF 支持在线预览；Word 和 Excel 提供下载。
- 本轮不为单条进度单独绑定附件，所有附件统一显示在事项详情的附件区。
- 复用现有 `FileAsset` 上传、权限校验、预览和下载能力，不建立第二套文件存储。

### 2.6 删除与恢复

- 超级管理员和普通管理员均可把事项删除到回收站。
- 软删除后，事项从普通列表、驾驶舱和相关对象详情中隐藏。
- 超级管理员和普通管理员均可从回收站恢复事项，恢复后保留原状态、关联、进度和附件。
- 只有超级管理员可以永久删除。
- 永久删除会删除事项、关联和进度，并通过现有文件服务释放附件关联；物理文件仅在确认无其他引用时清理。
- 永久删除前必须二次确认，并明确提示不可恢复。

## 3. 方案选择

采用“独立、规范化物业办事模块”方案：主事项、业务关联、进度记录和附件关联分别保存。

未采用以下方案：

- 单表加 JSON：初期代码少，但后续无法可靠筛选、反向查询和维护数据完整性。
- 通用可配置工单引擎：扩展性高，但当前需求不需要流程配置、审批节点或提醒，建设和使用成本过高。

独立模块与合同、收款、退租、房源状态逻辑解耦，只读取关联对象，不调用其业务写入接口。

## 4. 页面与交互

### 4.1 左侧导航

- 左侧导航新增一级入口“物业办事”。
- 入口仅对 `SUPER_ADMIN` 和 `ADMIN` 显示。
- `VISITOR` 不显示入口，直接访问前端路由时跳转无权限页或驾驶舱。

### 4.2 事项列表

列表顶部展示：

- 全部事项数量
- 待办理数量
- 办理中数量
- 已完成数量
- 已取消数量

列表支持：

- 关键词搜索：事项编号、标题、内容、外部办理人或单位。
- 分类、优先级、状态、内部负责人筛选。
- 按楼栋、房源、承租人或合同关联条件筛选。
- 分页展示。
- 默认按“最近更新时间倒序、事项 ID 倒序”排列。

表格主要字段：事项编号、标题、分类、关联对象摘要、负责人、优先级、状态、最近更新时间和操作。

### 4.3 新增与编辑

表单字段：

| 字段 | 规则 |
|---|---|
| 事项编号 | 系统自动生成，只读 |
| 标题 | 必填，最多 200 字 |
| 分类 | 选填，可输入或选择历史分类，最多 80 字 |
| 优先级 | 必填，默认普通 |
| 当前状态 | 新建默认待办理；编辑时按状态规则调整 |
| 内部负责人 | 选填，从有效系统用户中选择 |
| 外部办理人/单位 | 选填，最多 100 字 |
| 联系电话 | 选填，最多 50 字，不强制限定为手机格式 |
| 其他联系方式 | 选填，最多 200 字 |
| 事项内容 | 必填，使用普通多行文本，最多 5000 字 |
| 关联对象 | 选填，支持多选楼栋、房源、承租人和合同 |
| 附件 | 选填，复用现有文件限制 |

事项编号格式为 `WY + 创建日期 + 当日四位序号`，例如 `WY202609020001`。编号由后端在事务内生成并设唯一索引，前端不得自行拼接。

编辑页面回填完整当前数据。所有允许访问本模块的管理员均可编辑任意事项，不按创建人或负责人限制。

### 4.4 事项详情

详情页分为：

1. 事项标题、编号、状态和优先级。
2. 当前负责人、外部联系人、创建人、创建时间和最近更新时间。
3. 事项内容。
4. 已关联楼栋、房源、承租人和合同，可点击进入对应详情。
5. 附件列表及预览、下载操作。
6. 倒序进度时间线。
7. 编辑、追加进度、状态操作和删除操作。

追加进度时填写办理说明，并可同时选择新的当前状态。进度保存后不可编辑或删除；录入错误时通过再追加一条更正说明处理。

### 4.5 回收站

- 回收站单独分页展示已删除事项。
- 展示事项编号、标题、删除人、删除时间和删除前状态。
- `SUPER_ADMIN` 和 `ADMIN` 可恢复。
- 仅 `SUPER_ADMIN` 显示“永久删除”。

### 4.6 驾驶舱

- 驾驶舱新增“物业办事”列表，不只显示统计数字。
- 最多展示 8 条未完成事项，即状态为待办理或办理中且未软删除的事项。
- 排序规则为：紧急优先，其次重要、普通；同优先级按最近更新时间倒序、ID 倒序。
- 每条展示标题、关联对象摘要、负责人、状态、优先级和最近更新时间。
- 点击进入事项详情。
- 仅 `SUPER_ADMIN` 和 `ADMIN` 获取并看到该区块；`VISITOR` 不返回事项明细，也不看到空区块。

### 4.7 相关对象详情

- 房源详情、承租人详情和合同详情新增“相关办事事项”区块。
- 默认展示最近更新的若干条，支持进入完整筛选列表。
- 展示编号、标题、状态、优先级和最近更新时间。
- 已进入回收站的事项不展示。
- 楼栋关联用于事项详情和列表筛选；本轮不新增独立楼栋详情页。

## 5. 数据模型

### 5.1 枚举

新增：

- `PropertyAffairStatus`：`PENDING`、`IN_PROGRESS`、`COMPLETED`、`CANCELLED`。
- `PropertyAffairPriority`：`NORMAL`、`IMPORTANT`、`URGENT`。

前后端统一维护中文映射，不在界面直接展示枚举代码。

### 5.2 主事项 `PropertyAffair`

主要字段：

- `id`
- `affairNo`，唯一
- `title`
- `category`
- `priority`
- `status`
- `content`
- `responsibleUserId`
- `externalHandlerName`
- `externalPhone`
- `externalContact`
- `createdBy`
- `updatedBy`
- `completedAt`
- `cancelledAt`
- `deletedAt`
- `deletedBy`
- `version`，默认 1，用于乐观并发控制
- `createdAt`
- `updatedAt`

索引至少覆盖：事项编号、状态与删除时间、优先级与更新时间、负责人、分类和更新时间。

### 5.3 业务关联

分别建立楼栋、房源、承租人和合同关联表，避免把业务关联塞入 JSON。每张表至少包含事项 ID、目标对象 ID、关联时的显示文本快照和创建时间，并对同一事项与同一对象建立唯一约束。

服务层负责：

- 创建和编辑时验证目标存在。
- 查询时批量加载当前对象信息，避免逐行查询。
- 当前对象不可用时回退显示保存的文本快照。

### 5.4 进度 `PropertyAffairProgress`

主要字段：

- `id`
- `affairId`
- `content`
- `statusBefore`
- `statusAfter`
- `createdBy`
- `createdAt`

进度记录为追加型数据。普通编辑接口不得修改或删除既有进度。

### 5.5 附件关联 `PropertyAffairFile`

字段包括事项 ID、`FileAsset` ID、关联人和关联时间；事项与文件使用组合唯一约束。

附件必须先通过现有文件服务完成类型、大小、存储键和上传权限校验，再允许绑定到事项。

## 6. 后端组件与接口

新增独立 `PropertyAffairsModule`，包含 Controller、Service、DTO 和查询构建逻辑。建议接口：

- `GET /api/property-affairs`：分页、搜索和筛选；也用于相关对象反向查询。
- `GET /api/property-affairs/categories`：返回历史分类候选值。
- `GET /api/property-affairs/recycle-bin`：回收站分页列表。
- `GET /api/property-affairs/:id`：事项详情。
- `POST /api/property-affairs`：新建事项。
- `PATCH /api/property-affairs/:id`：编辑主事项、关联和当前状态，必须提交 `version`。
- `POST /api/property-affairs/:id/progress`：追加进度，可同时调整状态。
- `POST /api/property-affairs/:id/files`：绑定已上传附件。
- `DELETE /api/property-affairs/:id/files/:fileId`：解除附件关联。
- `DELETE /api/property-affairs/:id`：移入回收站。
- `POST /api/property-affairs/:id/restore`：恢复事项。
- `DELETE /api/property-affairs/:id/permanent`：永久删除，仅超级管理员。

现有驾驶舱接口增加 `propertyAffairs` 字段，由物业办事服务提供只读摘要。`VISITOR` 返回空数组或不包含该字段，前端均按无数据且无权限处理。

创建、编辑关联、追加进度、状态变化、删除和恢复均在数据库事务中完成。永久删除应保证事项、关联、进度和文件关系一致处理。

## 7. 权限与审计

| 操作 | 超级管理员 | 普通管理员 | 游客 |
|---|---:|---:|---:|
| 查看列表和详情 | 允许 | 允许 | 禁止 |
| 新增和编辑 | 允许 | 允许 | 禁止 |
| 追加进度和改变状态 | 允许 | 允许 | 禁止 |
| 删除到回收站 | 允许 | 允许 | 禁止 |
| 恢复 | 允许 | 允许 | 禁止 |
| 永久删除 | 允许 | 禁止 | 禁止 |

- 前端隐藏入口只是体验控制，所有接口必须由后端角色守卫再次校验。
- 普通管理员可以编辑和软删除其他管理员创建的事项。
- 所有写操作记录到现有 `OperationLog`，包括变更前后数据、事项编号、操作人、角色、时间和请求信息。
- 永久删除属于高风险操作，除操作日志外再写入现有 `SecurityAuditLog`；安全审计记录不随事项删除。

## 8. 并发、错误和数据一致性

### 8.1 并发编辑

- 编辑接口必须提交页面加载时获得的 `version`。
- 更新条件同时匹配 `id` 和 `version`，成功后版本加 1。
- 版本不匹配返回 409，中文提示“内容已被其他管理员更新，请刷新后重试”。
- 前端保留当前填写内容，不自动用服务器数据覆盖。

### 8.2 错误提示

- 参数缺失或格式不正确：返回明确中文字段提示。
- 事项不存在或已永久删除：返回 404“办事事项不存在”。
- 普通列表访问回收站事项：返回 404，避免误操作。
- 无权限：返回 403“无权操作物业办事事项”。
- 关联对象无效：指出具体对象类型和标识，整次保存回滚。
- 附件不支持、超限或上传失败：沿用文件模块中文提示；不得产生半绑定关系。
- 永久删除失败：事项和所有关联保持原状，不做部分删除。

### 8.3 与现有业务隔离

- 物业办事模块只能读取楼栋、房源、承租人和合同信息。
- 创建、编辑、完成、取消、删除或恢复事项均不得写入房态、合同、账单、收款、押金、退款或退租表。
- 财务总览、租金账单、收款统计和退租结算不得把物业办事事项计入口径。
- 数据库迁移只新增物业办事相关表、枚举、关系和索引，不修改或重算现有业务数据。

## 9. 前端组件边界

新增：

- `PropertyAffairsView`：列表、筛选和回收站入口。
- `PropertyAffairForm`：新增与编辑共用表单。
- `PropertyAffairDetailView`：详情、进度、附件和状态操作。
- `PropertyAffairRelationPicker`：混合关联选择器。
- `PropertyAffairTimeline`：只读进度时间线。
- `PropertyAffairsDashboardList`：驾驶舱摘要列表。
- `RelatedPropertyAffairs`：房源、承租人和合同详情复用的关联区块。
- `propertyAffairs` service 和类型定义。

状态、优先级和关联对象类型的中文标签集中维护，禁止在不同页面散落重复映射。

## 10. 测试与验收

### 10.1 后端单元测试

- 当日事项编号连续且并发创建不重复。
- 创建、编辑、追加进度和全部状态流转。
- 已完成、已取消事项重新开启。
- 历史分类候选去重且不返回空值。
- 混合多对象关联的创建、替换和查询。
- 关联对象无效时事务整体回滚。
- 乐观锁冲突返回 409，旧数据不被覆盖。
- 软删除、恢复和超级管理员永久删除。
- 普通管理员不能永久删除，游客不能访问任何接口。
- 驾驶舱只取未完成事项，数量和排序正确。
- 操作日志和永久删除安全审计正确写入。

### 10.2 前端单元测试

- 菜单和路由按角色显示或拦截。
- 表单校验、分类自由输入、负责人和混合关联选择。
- 列表搜索、筛选、分页和中文状态显示。
- 详情编辑、追加进度、完成、取消和重新开启。
- 图片/PDF 预览及 Word/Excel 下载入口。
- 回收站恢复及永久删除按钮权限。
- 并发冲突时保留用户输入并显示中文提示。
- 驾驶舱最多显示 8 条且排序正确。
- 房源、承租人、合同详情正确展示相关事项。

### 10.3 E2E 与回归

- 超级管理员完整流程：创建事项、关联多个对象、上传附件、追加进度、完成、重新开启、删除、恢复、永久删除。
- 普通管理员完整流程及永久删除拒绝。
- 游客菜单不可见、路由不可达、接口返回 403。
- 两个管理员使用同一版本并发编辑，后提交者收到冲突提示。
- 关联事项在房源、承租人和合同详情出现；软删除后同步消失，恢复后重新出现。
- 驾驶舱展示与事项列表状态、优先级和更新时间一致。
- 前后端全量单元测试、Lint、Prisma 校验和生产构建通过。
- 测试数据库迁移前备份；迁移不清空、不重建现有业务数据。
- 对房态、合同、租金账单、收款、财务总览和退租流程做只读前后对比，确认金额和状态均未变化。

## 11. 非目标

- 不设置计划完成日期、到期时间或提醒。
- 不加入驾驶舱今日待办提醒体系。
- 不增加审批流程、服务级别、自动派单或消息通知。
- 不记录费用，不与收款、账单或财务中心联动。
- 不因事项状态变化而自动修改房态、合同状态或承租人状态。
- 不建设分类管理页面。
- 不为单条进度绑定附件。
- 不允许游客查看物业办事数据。

## 12. 实施顺序

1. Prisma 模型、迁移和后端权限骨架。
