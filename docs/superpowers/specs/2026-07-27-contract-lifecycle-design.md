# 合同生命周期自动流转设计

## 目标

按冻结需求，让已确认合同在开始日进入履行中状态，并在结束日进入待退房状态；房源状态和房态历史与合同状态同步。

## 范围

- 合同开始日当天或之后：`PENDING_START` 转为 `ACTIVE`，写入 `activatedAt`；关联房源从 `PENDING_MOVE_IN` 转为 `RENTED`。
- 合同结束日当天或之后：`ACTIVE` 转为 `PENDING_CHECKOUT`；关联房源从 `RENTED` 转为 `PENDING_CHECKOUT`。账单已按结束日当天计租，该状态变化不修改账单。
- 每次房源变化必须新增 `room_status_histories` 记录，业务类型为 `CONTRACT`。
- 应用启动后立即补处理；随后每日执行一次，覆盖服务停止期间错过的日期。

## 明确不做

- 不自动将合同设为 `ENDED`；冻结规则要求完成退租结算和余额处理后才能结束。
- 不改动任何合同金额、优惠、账单快照、收款、退款或审批记录。
- 不为管理员新增手工“强制生效”入口，避免绕过合同开始日。
- 不修改已处于退租、结束或作废状态的合同。

## 处理规则

一次任务在数据库事务中分别处理两类合同。

1. 启动处理：筛选 `PENDING_START` 且 `startDate <= 当日` 的合同。更新合同与房源；若房源已不是 `PENDING_MOVE_IN`，仍更新合同但不覆盖房源人工后续状态。
2. 到期处理：筛选 `ACTIVE` 且 `endDate <= 当日` 的合同。冻结设计要求结束日期到达时转为待退房；结束日当天计租已由账单快照保证，状态变化不重算金额。更新合同与房源；若房源已不是 `RENTED`，仍更新合同但不覆盖房源人工后续状态。
3. 同一合同在同一轮任务中只执行与其当前状态匹配的一次转换，重复执行不会重复写入房态历史。

## 触发机制

- 新增 `ContractLifecycleService`，实现 Nest 生命周期启动钩子，在服务启动后执行一次补偿检查。
- 使用现有 Nest Schedule，每日 00:05 执行一次。
- 使用可注入的时钟参数或私有方法参数，保证单元测试不依赖真实日期。

## 权限与审计

这是系统自动任务，不提供用户调用接口；不新增可绕过权限的 HTTP 路由。
房态历史保留状态来源和合同编号。既有操作日志与安全审计模型不因本自动流转改变；本次范围不虚构人工操作人。

## 测试

- 开始日前不变；开始日与逾期开始合同正确生效，房源改为已出租并只写一次历史。
- 结束日当天及逾期结束合同正确进入待退房，房源同步并只写一次历史。
- 非匹配房源状态不会被任务覆盖；合同本身仍按规则流转。
- 已结束、作废、待退房合同不受影响。
- 模块编译、现有单元测试、接口测试、Lint 与 Prisma 校验完整运行。

## 验收方式

使用 `TEST-` 合同验证：启动服务或触发一次生命周期检查后，合同与房源状态一致，房态历史只新增一条；随后在结束日次日检查待退房状态。通过正式状态后，继续阶梯退差和退租结算验收。
