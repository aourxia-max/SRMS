# 退租结算退还租金验收记录

日期：2026-08-31

## 实施范围

- 退租结算新增“退还租金”，管理员只填写金额和说明，每张结算单最多一项。
- 后端按实际退房日、账期和有效租金实收计算最多可退金额；未来账期从晚到早，最后处理当前账期，同账单按收款日期和分配 ID 倒序。
- 提交结算时生成可审计的租金回冲预留；驳回、退回草稿、取消和合同纠错可释放预留。
- 普通退款、收款作废、另一退租结算与当前退租流程双向防止重复占用。
- 应退押金、应退预收款和应退租金合并为一次退款；客户端不能提交拆分金额。
- 最终确认在单一数据库事务中完成租金回冲、账单和收款状态更新、押金/预收款流水、凭证锁定、结算完成、合同结束和房态释放。
- 收款详情、财务中心、退租详情和合同纠错展示并追溯退租租金退款。
- 管理员、超级管理员和游客权限由后端强制校验，页面提示和状态使用中文。

## 手工验收步骤

1. 使用测试环境准备一份具有当前账期和未来账期有效租金实收的测试合同，发起提前退租并填写实际退房日期。
2. 在“退租结算”点击“添加退还租金”，确认只出现一项，且只要求填写退还金额和说明。
3. 核对页面显示“当前最多可退租金”和自动回冲明细；修改实际退房日期后确认上限和明细重新计算。
4. 输入超过上限的金额，确认前端阻止提交且后端返回中文错误；金额为0、负数或说明为空也必须拒绝。
5. 正常提交后核对结算进入等待确认，回冲明细显示“已预留”；再尝试对同一原收款提交普通退款或收款作废，系统应拒绝重复占用。
6. 驳回或退回草稿一次，核对旧预留显示“已释放”；重新提交应生成新的预留，不复用旧记录。
7. 用超级管理员确认结算，核对应退押金、应退预收款、应退租金和合计退款均为锁定值。
8. 用管理员登记一次合并退款并上传凭证；核对页面显示三类拆分和系统回冲明细，且无法手工修改拆分金额。
9. 用超级管理员执行“确认退款并完成退租”，核对：
   - 原账单净应收和有效实收同额减少，未收金额不增加；
   - 原收款显示“部分退款”或“已退款”，收款详情可查看退租租金退款及凭证；
   - 押金和预收款流水与锁定金额一致；
   - 财务中心只出现一笔合计退款的外部资金流；
   - 回冲预留变为“已回冲”，合同结束，房源进入结算时选择的目标房态。
10. 分别使用普通管理员和游客尝试确认结算或最终退款，确认后端返回无权限；前端隐藏入口不能代替该校验。
11. 对一笔只预留、尚未完成退款的结算执行已批准合同作废/纠错，核对预留释放、结算取消，不产生退款或账务回冲。
