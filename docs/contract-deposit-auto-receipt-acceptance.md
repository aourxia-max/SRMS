# 新合同押金自动入账验收记录

日期：2026-08-24
需求基线：`SRMS-RB-1.0` 及已批准变更 `SRMS-RB-1.0-CR-20260823-01`

## 验收范围

- 功能上线后新创建的合同中，填写押金即表示实际收到。
- 正数押金随合同创建原子生成一笔已确认 `DEPOSIT` 收款和一笔 `RECEIPT` 押金流水。
- 押金为 0 或仅保存合同草稿时不创建财务记录。
- 系统自动收款使用内部方式 `SYSTEM_AUTO`，前端显示“系统自动入账”，用户提交的手工收款方式不得使用该值。
- 自动初始押金使用唯一 `auto_source_key`，重复或并发来源不得重复入账。
- 现有合同不补记、不修改；当前押金余额继续以最新押金流水的 `balance_after` 为唯一依据。
- 财务中心仅由后端汇总每份合同最新押金余额，并显示“押金余额总额”。

## 实现结果

- Prisma `PaymentMethod` 新增 `SYSTEM_AUTO`。
- `payments` 新增可空唯一字段 `auto_source_key`，初始押金来源格式为 `CONTRACT_INITIAL_DEPOSIT:<contract_id>`。
- 合同创建事务接入 `ContractDepositService`；合同、押金收款、押金流水、账单和房态任一步失败时整体回滚。
- 自动初始押金禁止通过通用收款编辑、退款或作废入口操作；后续变动必须使用押金专用受控流程。
- `GET /api/finance/overview` 返回 `depositBalanceTotal`，并在后端强制限制为超级管理员。
- 合同表单、合同详情、收款详情、房源详情和财务中心已补齐中文标签；手工收款选择器不包含“系统自动入账”。
