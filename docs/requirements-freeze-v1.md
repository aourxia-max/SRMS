# SRMS 第一版需求冻结基线（V1.0，变更后）

> 项目：Smart Rental Management System（房屋租赁管理系统）  
> 基线编号：SRMS-RB-1.0  
> 冻结日期：2026-07-20  
> 状态：已冻结；适用已批准变更 `SRMS-RB-1.0-CR-20260805-01`、`SRMS-RB-1.0-CR-20260823-01`、`SRMS-RB-1.0-CR-20260826-01`

## 1. 基线效力

本文件是 SRMS 第一版开发、测试和验收的最高层需求基线。

- 已确认规则不再反复讨论，除非项目负责人明确提出变更。
- 文字需求和详细设计是验收依据；HTML 原型只用于表达页面布局和交互，不因原型暂时漏画某项功能而取消已确认需求。
- 发生冲突时，优先级为：最新已批准变更单 > 本冻结基线 > 模块详细设计 > 数据库设计 > 页面原型。
- UI 文案、间距、颜色等不改变业务含义的优化，可以在开发中调整；状态、权限、金额、流程、数据字段和统计口径不得自行改变。

## 2. 第一版范围

第一版包含：登录与三类角色、驾驶舱、房源、承租人、固定月租合同、租金账单、收款、优惠减免、押金、退租、财务中心、租房提成、文件、Excel/PDF 导出、系统设置、操作日志、安全审计和备份恢复。

第一版不包含：水费、电费、在线支付、发票、多公司 SaaS、已出售房源合同、已出售房源代管出租、提成自动计算或提成付款流程。

## 3. 冻结业务规则

### 3.1 角色与权限

- 角色固定为超级管理员、管理员、游客。
- 财务中心仅超级管理员可访问。
- 超级管理员可以直接修改已确认收款，但必须填写原因并永久保留修改前后值。
- 管理员不能直接修改已确认收款；错误收款采用申请作废后重录，作废由超级管理员确认。
- 管理员登记退款和押金退还，超级管理员确认。
- 超级管理员可以删除普通操作日志；页面删除实际为可恢复的隐藏，删除行为写入不可删除的安全审计日志。
- 系统必须始终保留至少一名启用状态的超级管理员。

### 3.2 房源

- 房源覆盖 1 栋、2 栋的住宅和商铺；保留楼栋、房号、完整房号、类型、面积、装修状态、用途、状态、业主和备注。
- 业主字段只作直观展示。
- 房态包含：已出租、空置、待入住、待退房、维修中、待出售、已出售、停用及其他。
- 待出售、已出售和停用不计入可经营房源。
- 已出售房源只保留房态和业主展示，不提供合同、收款或代管出租功能。
- 驾驶舱按楼栋展示全部房态和各状态数量，支持状态多选筛选与个人默认筛选。
- 不易理解的关键词或标签提供鼠标悬停说明。

### 3.3 承租人与合同

- 承租人类型默认“个人”，允许改为单位。
- 一份合同只对应一个房源，必须有一名主承租人，可以登记多名副承租人。
- 合同采用固定租期，缴费不会自动延长合同期限。
- 按合同开始日每满一个月形成账期；支持不足整月按日计租。
- 缴租周期可选择 1—12 个月，但实际收款可覆盖任意个月数，不受合同缴租周期限制。
- 支持部分付款、一次缴纳多个月和预收款。
- 新建合同仅支持固定月租；支持固定金额优惠、比例优惠、免租和优惠减免。
- 合同尾期按固定30天处理；账单在合同确认时生成不可覆盖的快照。

### 3.4 固定月租与人工退差

- 固定月租合同允许登记人工协商退差；不提供基于档位、达标期或参考公式的退差能力。
- 管理员登记人工退差，超级管理员确认；实际退款必须上传交易凭证，也可以按确认结果转为预收款。
- 人工退差采用补充记录，不覆盖历史账单、收款或既有退差记录。
- 不得新建阶梯合同或阶梯达标退差。历史阶梯合同及其关联业务、财务数据必须先备份、预检，再按受控清理流程完整删除。

### 3.5 账单、收款与优惠减免

- 合同生效后生成固定租期内的账单快照。
- 一笔收款可以分配到多张账单，默认按最早未结清账单分配，也可以选择未来账单。
- 金额不足时形成部分付款；超出已选账单的金额进入合同预收款余额。
- 一笔收款生成一张收据，列出覆盖账期和金额。
- 收款登记支持优惠或减免金额；原应收、已确认优惠和实际付款必须分开记录。
- 管理员提交优惠减免，超级管理员确认；待确认优惠不得提前减少应收。
- 优惠减免必须填写类型、金额、适用账单和原因；收据分别展示原应收、优惠和实付。
- 作废收款时回退与该收款绑定的一次性优惠；部分退款必须明确关联优惠的处理结果。

### 3.6 押金与退租

- 功能上线后新创建的合同中，填写的押金金额即表示该金额已经实际收到；合同正式创建时必须在同一数据库事务内生成一笔已确认的押金收款和一笔押金收取流水。
- 用户不需要另行填写押金收款日期、收款方式或收款凭证；系统以合同正式创建日期入账，收款方式记录为“系统自动入账”。押金为 0 时不创建零金额财务记录，草稿保存时不入账。
- 功能上线前已经存在的合同不补记、不修改。已有合同仅填写合同押金但没有押金流水时，当前押金余额仍为 0；已有真实押金流水继续有效。
- `contracts.deposit_required` 仅保存新合同创建时确认已收的初始押金；合同生效后的当前押金余额及退租可退金额，始终以该合同最新一笔不可覆盖押金流水的 `balance_after` 为唯一依据。
- 押金可以抵扣欠租和双方确认的验房扣款。
- 退租按“发起退租—验房与结算—押金退还确认”执行，退款跟随合同。
- 押金退还不填写收款人、退款账户后四位或交易流水号。
- 押金退还登记包含退款日期、退款方式和备注；转账必须上传交易截图，现金退还上传签收凭证。
- 管理员登记押金退还，超级管理员确认。
- 无可退押金时不创建虚假退款或凭证记录。
- 欠租、预收款和押金全部处理完成后，退款完成，合同结束；实际退租日后的未来账单作废。

### 3.7 财务与报表

- 财务报表同时提供账期经营口径和实际收付日期口径，两者不得混用。
- 财务中心顶部按“有效实收、押金余额总额、租金及押金入账合计、原应收、优惠减免、未收”展示，不显示“净应收”汇总卡片；净应收仍保留在明细、导出和后台计算中。
- “租金及押金入账合计”按实际收款日期汇总有效的租金、预收款和押金收款；作废收款、作废合同对应收款及退租补收不计入，退款作为资金流出独立展示且不倒扣历史入账。
- 租金净应收等于原应收扣除已确认免租和优惠并计入已确认调整。
- 收租率按“有效实收 ÷ 租金净应收”计算；净应收为零的账单不进入分母。
- 押金和未分配预收款属于负债，不计入租金收入；优惠不是付款或现金流出。
- 押金抵扣属于内部抵扣，不计入外部现金流。
- 财务中心展示“押金余额总额”，按每份合同最新一笔押金流水的 `balance_after` 汇总；不得累加历史余额快照，也不得直接汇总合同押金字段。
- 财务总览、租金收缴报表、资金流水支持规定的 Excel/PDF 导出，敏感导出永久审计。

### 3.8 租房提成

- 提成只有超级管理员可以查看、登记、修改、删除和导出；管理员和游客的页面、接口、导出及统计均不得返回提成字段。
- 提成金额由超级管理员主观填写，可随时修改，不受合同状态限制。
- 每条提成只需要所属合同、所属对象和金额。
- 不设置比例、计算基数、触发条件、审批、付款状态、支付日期、支付方式或凭证。
- 提成不进入租金应收、实收、收租率、优惠、押金、预收款或资金流水。
- 每次新增、修改和删除都把前后值写入不可删除的安全审计日志。

### 3.9 驾驶舱、日志与备份

- 驾驶舱包含经营指标、未来 7 天催租、欠租、合同到期、待审批事项和楼栋房态图。
- 普通操作日志可以查询；超级管理员页面删除后可恢复。
- 安全审计日志为只追加记录，业务接口不得修改或删除。
- 每天自动备份并保留最近 30 天；恢复前先备份当前数据，恢复操作永久审计。

## 6. 变更控制

冻结后提出的新需求不直接覆盖本文件，先建立需求变更单（CR），至少记录：变更内容、原因、优先级、目标版本，以及对页面、权限、数据库、接口、历史数据、报表和测试的影响。

批准后的变更执行以下规则：

1. 更新需求基线版本号。
2. 同步修改受影响的详细设计和数据库设计。
3. 补充迁移、兼容和回归测试方案。
4. 在变更记录中保留旧规则和生效版本。

### 6.2 已批准变更：合同作废／纠错

| 项目 | 内容 |
|---|---|
| 变更编号 | `SRMS-RB-1.0-CR-20260826-01` |
| 批准日期 | 2026-08-26 |
| 优先级 | 高 |
| 目标版本 | SRMS 第一版 |
| 变更原因 | 管理员可能把错误合同正式提交，并产生账单、收款、押金、预收款、退款、退租和房态影响，需要受控补救。 |
| 新规则 | 新增合同作废／纠错申请。原合同和关联记录永久保留，通过反向冲销使错误合同累计有效财务净影响归零；不区分现实资金是否到账，不要求退款凭证。 |
| 复杂历史 | 已完成退租、存在后续合同、财务已封账或存在待审批事项的合同仍可纠错；系统分别采用历史反向流水、保持当前房态和取消待审批事项等受控处理。 |
| 权限影响 | 管理员可以申请；只有超级管理员可以最终确认或驳回。超级管理员直接发起时必须完成风险二次确认。所有权限由后端强制校验。 |
| 数据影响 | 新增纠错单、逐项冲销明细、原始记录反向关联、唯一幂等来源和合同“已作废”最终状态；不物理删除或覆盖历史数据。 |
| 报表影响 | 驾驶舱和财务报表按冲销后的有效净值统计；封账历史在当前开放期间记录“历史合同纠错”，不改写原期间。 |
| 详细设计 | `docs/superpowers/specs/2026-08-26-contract-void-correction-design.md` |
| 测试影响 | 必须覆盖金额归零、复杂历史、房态保护、审批权限、并发幂等、事务回滚、报表一致性和中文化。 |
